# Altior v0.0.1 Developer Preview Release Notes

**Release Date:** 2026-08-31  
**Version:** `0.0.1`  
**Milestone:** P1.2 ACP Runtime Foundation Complete  
**Reference Target:** Windows 11 (x86_64 / MSVC) · Cross-Platform Rust Crates

---

## Executive Summary

Altior `0.0.1` is the initial **Developer Preview** release of the Altior local-first personal knowledge and agent runtime.

This release completes milestones **P0.1 through P1.2** of the [Implementation Plan](../IMPLEMENTATION_PLAN.md). It establishes the core backend runtime architecture, pure domain entity models, durable SQLite persistence with full-text search and projection self-healing, real ACP (Agent Client Protocol) subprocess execution over standard I/O, worker thread flow control backpressure, RAII process reaping, thread-level supervisor state machines, two-phase boundary checkpoints, crash safety without automatic turn re-sends, and end-to-end multi-process integration tests.

> **Note**: This release is a developer and architecture preview for runtime validation, contract verification, and test execution. It is **not** yet a packaged consumer application. Live wiring between the Tauri Desktop UI and the Core runtime daemon will land in the upcoming **P1.3 Desktop MVP** milestone.

## What's Included in 0.0.1

### 1. Real ACP Subprocess Runtime (`crates/altior-acp`)
- **Child process execution**: Invokes external agent binaries directly via `std::process::Command` using explicit `program` (`BoundedPath`) and `args` arrays (no shell interpolation).
- **Line framing & stream I/O**: Speaks newline-delimited JSON-RPC 2.0 over piped `stdin`/`stdout` streams with a 1 MiB line length cap (`MAX_LINE_BYTES`).
- **Bounded stderr capture**: Asynchronous reader thread captures child process `stderr` into a 64 KiB ring buffer (`MAX_STDERR_CAPTURE_BYTES`) with clear truncation notices.
- **RAII process reap (`KillOnDrop`)**: `AcpChild` implements `Drop` to terminate the subprocess, reap exit status via `wait()`, and join diagnostic capture threads, guaranteeing no orphan zombie processes are leaked.

### 2. Core Runtime Supervision & Coordination (`crates/altior-core`)
- **Port abstractions**: Core-owned traits (`HarnessRuntimePort`, `RuntimeCheckpointPort`, `AgentRuntime`) decouple domain orchestration from infrastructure adapters.
- **Thread supervisor state machine**: `ThreadRuntimeSupervisor` enforces strict lifecycle transitions (`Idle` → `Starting` → `Ready` → `Prompting` → `AwaitingPermission` → `Cancelling` → `Closed` / `Crashed`), a single active turn per thread limit, and `OperationRegistry` deduplication.
- **Worker threads & flow control**: `AcpHarnessAdapter` manages dedicated worker threads per session with 1024-bounded channels (`CHANNEL_BOUND`). An acknowledgement channel (`ack_tx` / `ack_rx`) throttles rapid streaming output to prevent unbounded memory growth.
- **Cancel signal & permission routing**: Atomic flags signal cancellations mid-stream; permission registries pause execution until user approval or denial is submitted.
- **UI detachment resilience**: Turn ownership in Core guarantees that active background agent turns continue executing and persisting even if the desktop UI window is reloaded or disconnected.

### 3. Domain Entities & SQLite Persistence (`crates/altior-domain`, `crates/altior-storage`)
- **Pure domain entities**: 8 domain classes (`AgentProfile`, `AcpHarnessBinding`, `Thread`, `Turn`, `Permission`, `ProjectRef`, `DomainEvent`, `EventPayload`), kind-prefixed identifier newtypes (`AgentProfileId`, `HarnessBindingId`, `ThreadId`, `TurnId`, `OperationId`, `EventId`, `CoreInstanceId`, `ProjectId`), bounded value objects, limits, and composite cursors.
- **Authoritative event journal & projections**: Dual journal architecture where `domain_journal` is the authoritative source for domain entities and rebuildable projections (`thread`, `turn`, `permission`).
- **Schema v4 migrations**: Forward migrations v1→v2→v3→v4 adding `runtime_checkpoint` and `thread_session_binding` tables.
- **Two-phase intent checkpoints**: Pre-call `CheckpointIntent` is durably written before external boundary calls; post-call outcomes settle to `Confirmed`, `Rejected`, or `Indeterminate`.
- **Startup recovery**: On database open, lingering `Intent` checkpoints atomically transition to `Indeterminate`.
- **Strict no-auto-resend rule**: Turns settling to `Indeterminate` or terminal states strictly forbid automatic retry on the same turn; explicit user action with fresh turn/operation IDs is required.
- **FTS5 search & projection self-healing**: Safe literal search with title clearing and official integrity checks (`rank='integrity-check', 1`), with FNV-1a projection digests verifying projection integrity on startup.

### 4. Secret Boundary & Redaction
- **Opaque secret references (`SecretRef`)**: Plaintext secrets are never stored in launch configurations or persisted to disk.
- **`NoSecretsResolver` seam**: Safe fail-closed default resolver when no platform credential vault is wired.
- **Canary validation**: Automated tests verify that secret canary values never leak into domain journals, checkpoint diagnostics, or SQLite database files.

### 5. Desktop Virtualized Workbench Spike (`apps/desktop`)
- **5-region shell**: Activity rail, thread list, virtualized timeline, prompt composer, and inspector regions.
- **Zero-dependency virtualized timeline**: Handles 100,000 items with prepend-stable history, streaming deltas, scroll restoration, and keyboard navigation with inline permission approval.
- **DTO generation**: TypeScript DTO contracts generated directly from Rust protocol types.

## Testing and Verification

The entire workspace is backed by extensive automated unit and end-to-end integration test suites:

- **160+ Rust tests** across 9 crates passing cleanly with zero warnings:
  - `p12_composition.rs`: Real OS subprocess execution with `mock_acp_agent` verifying happy path, exit code 42 crash handling, permission routing, cancellation, secret canary isolation, and multi-run process reap.
  - `p12_runtime.rs`: Supervisor state machine, streaming events, capability gates, single-turn limits, transport failures, UI detachment resilience, and resend prohibition.
  - `checkpoint.rs`: Schema v4 migration, intent recording, settlement transitions, reopen recovery to `Indeterminate`, and session binding CRUD.
  - `process_adapter.rs`: Real subprocess spawn, line I/O, stderr capture, and RAII drop termination.
  - `domain.rs`: 67 domain persistence tests covering CRUD, FTS5 search, collision detection, and projection self-healing.
- **39 Desktop vitest suite**: Virtualized timeline rendering, scroll pinning, keyboard shortcuts, and state transitions.

### Running the Test Suite

```bash
# Run all workspace unit and integration tests
cargo test

# Run P1.2 runtime and real subprocess composition tests
cargo test --test p12_composition --test p12_runtime --test checkpoint --test process_adapter

# Run Desktop UI test suite
npm --prefix apps/desktop test
```

## Building and Development

### Prerequisites
- **Rust**: 1.90.0 or higher
- **Node.js**: 20.x or higher (for `apps/desktop`)
- **Operating System**: Windows 10/11 (Reference platform), macOS, or Linux

### Building Crates and Mock Agent
```bash
# Build entire Rust workspace
cargo build

# Build the mock ACP agent binary used in integration tests
cargo build -p altior-acp --bin mock_acp_agent

# Run Desktop development shell
cd apps/desktop
npm install
npm run dev
```
