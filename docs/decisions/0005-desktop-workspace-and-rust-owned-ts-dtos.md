# ADR 0005: Desktop workspace and Rust-owned TypeScript DTO generation

- Status: Accepted
- Date: 2026-08-29

## Context

P0.1 requires the Desktop side to consume the same contracts the Rust side
enforces: one schema source for the wire types, and a runnable shell proving
the generated DTOs, the transport boundary, and the shared fixtures work end
to end. `docs/UI_ARCHITECTURE.md` fixes the directory layout, semantic
tokens, and the rule that feature code never touches Tauri or any transport
directly; ADR 0003 defers real Tauri wiring to P0.4, so the shell must run on
an in-memory transport. AGENTS.md forbids undocumented frameworks and
requires deterministic tests on both sides.

Constraints:

- Exactly one source of truth for contract types (AGENTS.md, ADR 0004).
- `altior-domain` stays platform-neutral and must not grow codegen
  dependencies; `altior-protocol` already owns the wire DTOs.
- Desktop tests must be deterministic: no timers, no randomness, no network.
- Fixture data is synthetic and Rust-owned; Desktop must not fork it.
- The desktop app must build and typecheck with strict TypeScript before any
  Tauri shell exists.

## Decision

### Workspace and toolchain

1. The Desktop app lives in `apps/desktop` as `@altior/desktop`, private,
   `"type": "module"`, with Vite + React + TypeScript + Vitest per ADR 0003.
   Tauri, `src-tauri/`, and `platform/tauri/` arrive with the P0.4 spike;
   nothing in P0.1 depends on them.
2. All npm dependencies are pinned exactly (`npm install --save-exact`).
   No monorepo tooling (workspaces, Nx, turbo): there is exactly one JS
   package; adding orchestration now would be undocumented framework risk.
3. TypeScript runs strict with `noUncheckedIndexedAccess`,
   `verbatimModuleSyntax`, `isolatedModules`, and `noEmit`; `typecheck` and
   `build` both run `tsc --noEmit` so type drift cannot ship.
4. Vitest runs with explicit imports (`globals: false`); the setup file
   registers Testing Library cleanup explicitly because auto-cleanup cannot
   detect the framework without globals.

### DTO generation: ts-rs behind a cargo feature

1. TypeScript DTOs are generated by ts-rs 12 from the `altior-protocol` DTO
   definitions, behind the optional `dto-export` cargo feature. The default
   feature set stays generator-free, so building or testing the workspace
   never requires the export path.
2. Generated files are committed to `apps/desktop/src/ipc/dto/`. They are
   the Desktop contract, reviewable in diffs, and identical on every
   regeneration (declaration order, no timestamps beyond the generator
   header). Regeneration: `cargo test -p altior-protocol --features
   dto-export`.
3. `altior-domain` types appear in DTOs through field-level ts-rs `type`/`as`
   overrides on the protocol structs (for example `type = "string"` on ID
   fields, `as = "Option<String>"` on nullable IDs, `as =
   "BTreeMap<String, CapabilitySupport>"` on capability maps). The domain
   crate keeps zero codegen dependencies; annotations live one layer up
   where the wire shapes are defined.
4. Generated-file drift is caught on both sides: the desktop suite imports
   the Rust fixtures through these types (a renamed field fails typecheck),
   and the Rust fixture suite pins the JSON byte-for-byte.

### Shared fixtures

1. Fixtures stay in `crates/altior-protocol/fixtures/` (Rust-owned). Desktop
   imports them directly as JSON modules; Vite's `server.fs.allow` permits
   reading outside the app root at dev/test time. There is one durable
   fixture source, not a per-language copy (AGENTS.md).
2. The imports are cast (`as unknown as T`) because JSON module inference
   widens unions (for example `"supported"` becomes `string`). The cast is
   sound only because the Rust suite validates and re-encodes each fixture
   byte-for-byte; the comment at the cast site records that justification.
3. Unknown-event fixtures come in two shapes: the raw provider form
   (`event-unknown-future-v1.json`, exercises wrapping) and the preserved
   form (`event-unknown-preserved-v1.json`, the fixed point Core re-emits,
   which is exactly what Desktop receives and replays). Desktop imports the
   preserved form so its DTO types hold at runtime, not just at compile time.

### Transport boundary and fixture shell

1. `src/ipc/transport.ts` defines `DesktopTransport` (handshake, subscribe,
   send). All feature code programs against this interface; the production
   transport chosen in P0.2 implements it, and `platform/tauri/` remains the
   only place allowed to import Tauri APIs.
2. `src/ipc/inMemoryTransport.ts` is the test/dev fake: synchronous fixture
   replay in stream-sequence order on subscribe, recorded commands, no
   timers, no network, no randomness. `structuredClone` isolates callers
   from shared mutable fixture state.
3. The fixture shell (`src/app/App.tsx`) renders the negotiated version and
   capabilities in a status bar, the event timeline from fixtures (unknown
   events as bounded diagnostic rows), and a disabled composer placeholder
   for the future turn input. Styling uses only the semantic tokens in
   `src/styles/tokens.css` (colors, spacing, typography, geometry,
   elevation, motion, reduced-motion), per `docs/UI_ARCHITECTURE.md`.

## Alternatives

- **Handwritten TS mirrors of the Rust DTOs.** Two sources of truth; field
  drift surfaces as runtime bugs instead of compile errors. Rejected.
- **schemars → JSON Schema → quicktype.** Keeps one source but adds a
  schema dialect and a second toolchain; weaker ergonomics for Rust
  enum/tagged-union mappings, and bounded-text semantics live in Rust
  validation anyway. Rejected for now.
- **Put ts-rs derives in `altior-domain`.** Would drag a TS generator into
  the platform-neutral crate and its dependency-boundary test. Rejected;
  field-level overrides in the protocol layer achieve the same output.
- **Ship a mock HTTP/WebSocket server (MSW) for the fixture shell.**
  Implies a network transport that does not exist until P0.2; also
  non-deterministic timing. Rejected; the in-memory fake is synchronous.
- **npm workspaces now.** One package; revisit when a second JS package
  (for example a shared fixture player or lint config) appears.

## Failure modes

- **ts-rs major bump changes attribute syntax** (v12 already removed
  `transparent`). Pinning the exact version plus localizing annotations to
  the protocol crate keeps the blast radius small; upgrades are a single
  reviewed change.
- **Someone hand-edits a generated file.** The generator header marks files;
  any regeneration overwrites the edit. The Rust-side fixture suite and the
  desktop typecheck together fail loudly on contract drift.
- **Rust fixture renames break desktop imports.** Fails at desktop
  typecheck/test time (module resolution), not silently.
- **Vite `fs.allow` is dev-server-only.** Imports are bundled at build time,
  so production builds never read outside the root at runtime. If the
  bundler ever refuses cross-root imports, move fixture JSON through the
  DTO-generation step instead (see Exit strategy).
- **`structuredClone` availability.** Node 17+ (dev/test) and all target
  browsers (2022+) provide it; the transport fake is the only user.

## Migration path

- P0.2 adds a production `DesktopTransport` implementation behind the same
  interface; the fake remains the component-dev and test harness that
  `docs/UI_ARCHITECTURE.md` requires.
- When Desktop gains real screens, `features/`, `stores/`, and `primitives/`
  fill in per the architecture doc; the shell stays as the minimal
  composition example.
- If a second JS package appears, introduce npm workspaces at the repo root
  before adding any cross-package imports.

## Exit strategy

- If ts-rs becomes unmaintained, the committed `.ts` files remain valid
  contracts; either freeze them and review changes by hand, or swap the
  generator. The annotations are attributes on protocol structs, not a
  parallel schema, so switching generators touches one crate.
- If the Desktop stack leaves Vite, only `vite.config.ts`, the dev-server
  `fs.allow` escape hatch, and the build script change; DTOs, fixtures, the
  transport interface, and tests are bundler-agnostic.

## Revisit when

- The P0.2 IPC ADR lands (production transport, catch-up semantics).
- A second JavaScript/TypeScript package joins the repository.
- ts-rs 13 or a successor generator becomes the maintained path.
