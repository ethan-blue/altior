# Altior 全面评审与 AI 执行包 / Review & execution pack

评审日期：2026-09-05。代码基线：`f945ef153eb3344abd3801a3c2e4002fd25d80be`。

这是基于代码、契约、实际测试和浏览器截图的多角色评审，不是对尚未交付功能的营销说明。此次只新增评审资料，没有修复产品代码。后续 AI 必须在自己的 checkout 重新核对问题，不能把本报告当作实时状态。

## 阅读和使用顺序

1. [完整评审报告（中文）](REVIEW.zh-CN.md)：结论、证据、严重程度、产品与技术意见。
2. [设计与中英文规范](DESIGN_I18N.md)：布局、主题、颜色、字体、交互、术语和验收矩阵。
3. [具体任务包](TASKS.md)：按依赖顺序执行的 20 个工作项；每项都有边界和验收。
4. [中文总提示词与持续工作规则](PROMPTS.zh-CN.md)：交给中文工作的 AI。
5. [English master prompt and execution rules](PROMPTS.en.md)：交给英文工作的 AI；同样读取任务包，不能另建一套产品要求。
6. [验证记录与复现材料](evidence/VERIFICATION.md)：运行了什么、没运行什么、截图解释和临时探针。

最简单的启动方式：复制中文或英文文件中的“总提示词”，让 AI 从 `A01` 开始。每完成一个工作项，要求它更新检查点；换 AI 时给下一位相同总提示词和检查点路径。不要只发送“继续优化”。

## 核心判断

保留 local-first、Core/协议/领域分层、ACP-first、日志与投影分离、可解释记忆、语义主题令牌。先修真实桌面端闭环，再做记忆产品化；同步上线前另过安全门槛。

当前不建议把“P1.4/P2.2 模块测试完成”解释成“真实第三方 ACP + 打包桌面 + 普通用户旅程已经完整”。最紧迫的问题包括不合法的前端 ID、演示状态进入正常应用、错误被当成功、历史没有真实正文、布局错位和中文输入误发送。

本包是审查建议和待执行工作约定，不自动替换已接受 ADR。建议与已接受 ADR 冲突时，后续实现者必须先在 `docs/` 中完成明确的决策更新。这里的任务状态全部是 **TODO**，不会因为报告已经写完就变成完成。
